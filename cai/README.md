# CAI

Calculate the Codon Adaptation Index (CAI) of a coding sequence, and ask what
that number actually means.

## Why

The CAI is routinely used to judge how well a coding sequence is adapted to
its host, but different tools give different values for the same sequence.
Before trusting a threshold, or comparing two variants scored by two
different sources, it is worth knowing exactly what is being computed and
against what.

## What's here

`cai.py` implements the calculation from first principles, following Sharp &
Li (1987), with every methodological choice (which codons are excluded,
which reference table is used) explicit rather than hidden inside a black
box. It also includes the building blocks needed to generate random
synonymous variants of a protein: translation, a synonym table, and a
biased random sampler.

`analysis.ipynb` uses the module to answer three questions on real data:

1. Does the exact definition (excluding stop codons and single-codon amino
   acids, or not) change the result on real sequences?
2. Does the reference table matter? The same six sequences are scored here
   and compared to [JCat](https://www.jcat.de/), a widely used codon
   adaptation server.
3. Can CAI and GC content be optimised independently? A thousand random
   synonymous variants of firefly luciferase are generated across a range
   of codon bias to find out.

The short answer: the definition barely moves the index on full-length
sequences, the reference table can change it by more than 0.3, and CAI and
GC content are tightly linked (Spearman correlation of 0.96) across the full
range explored, though locally at moderate bias there is a modest margin (a 
few percentage points of GC content, small next to the roughly 25 points 
spanned by the full curve) to generate variants at similar CAI with 
different GC content.

## Usage

```
python cai.py codon_table.txt sequences.fasta
```

Prints one CAI value per sequence found in the FASTA file. The reference
table must be in Kazusa format (species 9606 for human, standard genetic
code), as downloaded from the
[Kazusa Codon Usage Database](https://www.kazusa.or.jp/codon/cgi-bin/showcodon.cgi?species=9606).

## Files

- `cai.py`: the module (standard library only, no dependencies).
- `kazusa.txt`: human codon usage table, Kazusa database, standard genetic
  code, downloaded 2026-09-08.
- `CDS_sequences.txt`: six coding sequences for firefly luciferase, produced
  by four different codon optimisers, used in the comparison section of the
  notebook.
- `analysis.ipynb`: the full analysis, described above. Requires `pandas`,
  `matplotlib` and `scipy` in addition to `cai.py`.

The human proteome file used to rank amino acid frequencies is not included
because of its size; its provenance and exact retrieval query are given in
the notebook, and the relevant outputs are kept in the notebook so they can
be read without re-running that cell.

## Limitations

See the notebook's own limitations section for the full list. In short: no
consensus reference table exists for highly expressed human genes, the
synonymous variants are generated by biased random sampling rather than by
a real optimiser, and secondary structure is not modelled here even though
it moves together with CAI and GC content during real codon optimisation.

## Context

This project was built from scratch to answer a question I encountered in 
my own work: calculating the CAI of mRNA coding sequences for optimisation, 
and noticing that different tools gave inconsistent results for the same 
sequence.
